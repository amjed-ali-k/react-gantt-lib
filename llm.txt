# react-gantt-lib — AI agent reference

Package: react-gantt-lib v0.1.10
Purpose: High-performance React Gantt chart. Granular per-task bar updates (not full-chart re-render). Three draggable sidebar panels. Async custom rows (inline footer or sticky top/bottom). Sticky task bars and custom rows stay visible while scrolling large schedules. date-fns for all date math.

## Agent discovery (installed package)

When installed from npm, this file ships at:
- `node_modules/react-gantt-lib/llm.txt`
- Package export: `react-gantt-lib/llm.txt`

Read this file before integrating or extending the chart API.

## Install

npm install react-gantt-lib date-fns react react-dom

import { GanttChart } from 'react-gantt-lib';
import 'react-gantt-lib/styles.css';

Peer deps: react >=18, react-dom >=18. Node >=18.

## Minimal usage

<GanttChart
  tasks={[
    { id: '1', name: 'Design', start: '2026-01-01', end: '2026-01-15', progress: 65 },
  ]}
  height={500}
  zoomLevel="week"
  onTasksChange={(tasks) => setTasks(tasks)}
/>

Dates: ISO strings ('2026-01-01', '2026-04-22T14:00:00') or Date objects.

## GanttTask

Required: id, name, start, end
Optional:
- progress: number (0–100, default 0)
- parentId: string — hierarchy; child rows indented 16px per level
- collapsed: boolean — hide descendant rows and timeline bars when true
- type: 'task' | 'milestone' | 'group' — milestone = diamond; group = parent/summary row
- showSummaryBar: boolean — on group rows only; default true. false = sidebar folder only (no summary bar; children keep their own bars)
- rollup?: GroupSummaryRollup — per-group summary bar roll-up overrides (see Group rows & collapse)
- readOnly: boolean — disables drag, resize, and progress edits for this task
- enableDrag, enableResize, enableProgressDrag: boolean — per-task overrides (fall back to chart-level props)
- dependencies: string[] | GanttDependency[] — see Dependencies
- baseline: { start, end, color? } — original plan overlay (amber default #e6a23c)
- color: string — bar fill / milestone color
- borderColor: string — bar outline
- width: number — bar height in px within row (not bar length)
- sticky: 'top' | 'bottom' — pin row to top (below header) or bottom of scroll viewport; stays visible while scrolling
- meta: Record<string, unknown>

Task order in array = row order. Hidden descendants filtered by resolveTasks when any ancestor has collapsed: true.

## Group rows & collapse

type: 'group' — parent row for hierarchy and optional summary timeline bar.

| showSummaryBar | Timeline behavior |
|----------------|-------------------|
| true (default) | Summary bar on the group row (rolled-up dates/progress/baseline); child bars render when the group is expanded |
| false | No bar on group row; children render their own bars |

Sidebar collapse/expand (built-in):
- Parent rows with type: 'group' OR any task with children show a ▸/▾ button in the first column
- Click toggles task.collapsed; updates via onTasksChange when used with controlled tasks
- Collapsed ancestors hide all descendant rows (sidebar + timeline)
- Summary bar on collapsed groups still reflects all descendants (dates, progress, baseline)

### Summary bar roll-up

For `type: 'group'` with `showSummaryBar: true` (default), the group header bar rolls up:

| Field | Default | Override |
|-------|---------|----------|
| Dates | min(child start) / max(child end) | `rollup: { dates: false }` — use `start` / `end` on the group row |
| Progress | duration-weighted average of children | set `progress` on the group row, or `rollup: { progress: false }` |
| Baseline | min/max of child baselines | set `baseline` on the group row, or `rollup: { baseline: false }` |

Force roll-up even when a value is set on the group: `rollup: { progress: true }` or `rollup: { baseline: true }`.

Chart-level defaults: `groupSummaryRollup?: GroupSummaryRollup` on GanttChart (per-task `rollup` overrides).

When a field is rolled up, drag/resize/progress edits for that field are disabled on the group bar. Set the matching `rollup.*` flag to false (or set an explicit value for progress/baseline) to make it editable.

Roll-up uses all descendants in the tasks array (not only visible rows), so collapsed groups keep the full summary.

Helpers (internal, not exported from package entry): isGroupTask, groupShowsSummaryBar, shouldRenderTaskBar, taskHasChildren, taskSupportsCollapse, computeGroupSummaryRollup in src/core/groupTasks.ts

Example — folder vs summary group with roll-up:
[
  { id: 'phase', name: 'Phase 1', type: 'group', showSummaryBar: false, start: '2026-04-01', end: '2026-04-01' },
  { id: 'a', name: 'Task A', parentId: 'phase', start: '2026-04-02', end: '2026-04-06', progress: 100 },
  {
    id: 'envelope',
    name: 'Envelope',
    type: 'group',
    start: '2026-04-10',
    end: '2026-04-10',
    progress: 35,
    baseline: { start: '2026-04-08', end: '2026-04-14' },
  },
  { id: 'roof', name: 'Roofing', parentId: 'envelope', start: '2026-04-10', end: '2026-04-12', progress: 30, baseline: { start: '2026-04-09', end: '2026-04-11' } },
]

`envelope` uses explicit progress (35) and baseline unless `rollup.progress: true` / `rollup.baseline: true`. Dates still roll up from children unless `rollup.dates: false`.

## Display timezone

timezone?: string — IANA timezone id (e.g. `America/New_York`, `Asia/Tokyo`, `UTC`). Default undefined = browser local timezone.

**Display only** — does not change stored task dates, drag/snap math, timeline range, bar positions, or callback payloads (those remain real Date instants / ISO strings).

When set, all on-screen date/time labels use that zone for every viewer worldwide:
- Timeline header labels (upper + lower bands)
- Middle panel start/end columns
- Built-in task tooltip start/end (time shown when non-midnight in the display zone)

Not affected: bar geometry, today marker position (current instant), holiday day placement, block range geometry, event marker x position, onTaskDragEnd dates, onTasksChange data.

Example — global team sees New York time:
<GanttChart tasks={tasks} timezone="America/New_York" showTooltip />

Custom column/tooltip UI inside the chart tree:
import { useGanttDisplayTimezone } from 'react-gantt-lib';
// Inside GanttChart descendant:
const timezone = useGanttDisplayTimezone();
// Use with formatTaskDateTime from src/core/dates (internal) or your own Intl formatting

Hook: useGanttDisplayTimezone() — returns string | undefined. Must be descendant of GanttChart (GanttDisplayProvider). Undefined = browser local.

Implementation: GanttDisplayProvider + Intl.DateTimeFormat in src/core/displayFormat.ts. formatScaleHeader, formatScaleSubHeader, formatTaskDateTime accept optional timeZone param internally.

| day | Day | 1 day | 48 |

| 3hour | 3 Hours | 3 hours | 48 |
| 1hour | 1 Hour | 1 hour | 40 |
| hour | Hour | 1 hour | 64 |

- availableZoomLevels: string[] — toolbar +/− steps through this list; default month→week→day→hour→minute

Toolbar: built-in − / label / +. Zoom preserves viewport center on change.

computeTimelineRange(tasks, scaleOrId, paddingUnits=2, { minDate?, maxDate? })
Returns TimelineRange: { start, end, columnCount, pixelWidth?, fixed? }

## Fixed timeline range

Set BOTH minDate AND maxDate:
- Grid locked; does not grow when tasks dragged outside
- Task dates clamped to window on drag (move + resize)
- range.fixed = true; pixelWidth computed exactly to maxDate end-of-day

Without both bounds: range auto from task min/max + paddingUnits (default 2 columns each side).

## Snap vs smooth drag

snapToGrid: default true
| true | Smooth visual drag; dates snap to grid column boundaries on pointer release |
| false | Pixel-precision dates on release (sub-hour at hour/minute zoom) |

enableDrag: default true — move bar body (per-task override: GanttTask.enableDrag)
enableResize: default true — left/right handles on bar hover (per-task: enableResize)
enableProgressDrag: default true — bottom progress handle (per-task: enableProgressDrag)
readOnly: true on a task — disables drag, resize, and progress for that task

Milestones: draggable (move only); no resize handles.

Interaction:
- Click row (sidebar) or bar → onTaskClick + selection; Ctrl/⌘+click toggles multi-select
- Double-click bar → onTaskDoubleClick
- Hover bar or sidebar row → onTaskHover (enter/leave only; see Tooltip); resize handles appear (CSS .rg-bar:hover)
- Drag emits taskDragStart → taskDrag → taskDragEnd
- Resize emits taskResizeStart → taskResize → taskResizeEnd
- Progress emits progressChange
- Unified click/context-menu on bars, baselines, blocked dates, holidays, event markers, timeline → onGanttClick / onGanttContextMenu (see below)

onTasksChange(tasks) — full updated array after drag/resize/progress commit. Use for controlled state.

## Click & context menu (unified targets)

onGanttClick and onGanttContextMenu receive GanttPointerDetail:
{ target: GanttTarget, clientX, clientY, ctrlKey?, metaKey?, shiftKey?, preventDefault() }

onGanttHover receives GanttHoverDetail:
{ target: GanttTarget | null, phase: 'enter' | 'leave' | 'move', clientX, clientY }
Fires for blocked dates and holidays on the interaction layer (areas not covered by task bars).
Pass onGanttHover (or onGanttClick / onGanttContextMenu) to enable date-marking hit targets.

GanttTarget discriminated union (switch on target.type):

| type | When | Key fields |
|------|------|------------|
| task | Click/right-click task bar or milestone diamond | task, rowIndex, element: 'bar' \| 'milestone' |
| baseline | Click/right-click baseline line or diamond | task, rowIndex, element: 'bar' \| 'milestone' |
| blockDate | Click/right-click blocked date/time range band | range (BlockDateRange), index |
| holiday | Click/right-click holiday/weekend band | date, label?, index? |
| eventMarker | Click/right-click vertical event stripline | marker (EventMarker), index |
| timeline | Click/right-click empty timeline body or header | date (at pointer x), rowIndex (number \| null; null in header) |

Activation:
- Pass onGanttClick, onGanttContextMenu, and/or onGanttHover to enable overlay hit targets (timeline, blocks, holidays, baselines, event markers).
- Task bars always fire onTaskClick; also fire onGanttClick when that handler is set.
- Right-click: call e.preventDefault() in onGanttContextMenu to suppress the browser menu.

Click priority (top wins): task bar → baseline → blocked/holiday band → empty timeline.

onTaskClick / onTaskDoubleClick include optional element: 'bar' | 'milestone' and modifier keys ctrlKey, metaKey, shiftKey.

Example — block hover tooltip:
<GanttChart
  blockDates={[{ start: '2026-04-07T06:00:00', end: '2026-04-07T18:00:00', label: 'Curing — no pours' }]}
  onGanttHover={({ target, phase }) => {
    if (target?.type === 'blockDate' && phase === 'enter') showTip(target.range.label);
    if (phase === 'leave') hideTip();
  }}
/>

Example — custom context menu:
<GanttChart
  tasks={tasks}
  blockDates={[{ start: '2026-04-14', end: '2026-04-16', label: 'Offsite' }]}
  onGanttContextMenu={(e) => {
    e.preventDefault();
    const { target } = e;
    if (target.type === 'task') openMenu(e.clientX, e.clientY, ['Edit', 'Delete'], target.task);
    if (target.type === 'blockDate') openMenu(e.clientX, e.clientY, ['Clear block'], target.range);
    if (target.type === 'timeline') openMenu(e.clientX, e.clientY, ['Add task'], target.date);
  }}
/>

Example — switch on click target:
onGanttClick={(e) => {
  switch (e.target.type) {
    case 'task': selectTask(e.target.task.id); break;
    case 'baseline': showBaselineDiff(e.target.task); break;
    case 'eventMarker': scrollToDate(e.target.marker.date); break;
    case 'timeline': createTaskAt(e.target.date, e.target.rowIndex); break;
  }
}}

## Dependencies

dependencies on successor task points to predecessor id(s). One link per predecessor/successor pair; link id = dependencyId(fromId, toId) = "from->to".

Types (GanttDependency.type, default FS): FS end→start, SS start→start, FF end→end, SF start→end.
Rendering: orthogonal SVG path + arrowhead into the successor edge; backwards cases double back through the row gutter; milestones attach at the diamond's left (start) / right (end) tip.
lag: drawn as a label (+2d / -1d); formatDependencyLag?: (lag, dependency) => string overrides ('' hides). Lag does not move bars.
Per link: color (line, head, label), className (on the link <g>), critical (rg-dependency--critical).

Formats:
- ['task-a', 'task-b']
- [{ id: 'task-a' }, { id: 'task-b', type: 'SS', lag: 2, color: '#e11d48', critical: true }]

Interactive links (off by default) — enabled by any of onDependencyClick, onDependencyHover, onDependencyContextMenu, onDependencyDelete, or selectedDependencyIds:
- each link gets a 12px invisible hit stroke (only pointer-events target), first child of the bars SVG (bars paint over it)
- click / Enter / Space selects (ctrl/meta toggles); plain click on a task or link replaces both selections
- onSelectionChange({ selectedIds, selectedDependencyIds }); selectedDependencyIds?: string[] for controlled
- Delete/Backspace with links selected (focus in chart, not in input/textarea/select/contenteditable) → onDependencyDelete({ dependencies: GanttDependencyTarget[] }); chart removes nothing
- dependencyClick/dependencyContextMenu: GanttDependencyPointerDetail; dependencyHover: { target, phase: 'enter'|'leave', clientX, clientY }
- ganttClick / ganttContextMenu / ganttHover also receive GanttTarget { type: 'dependency', id, from, to, dependency }
- hit stroke: role=button, tabIndex=0, aria-pressed, aria-label "Dependency: A finish to start B, lag +2d"

Exports for extensions: dependencyId, collectDependencyTargets, computeDependencyLinks, DependencyLink, DEPENDENCY_EDGES, routeDependency, buildDependencyPath.

## Holidays / blocked dates / event markers

holidays?: HolidayMarking
- weekends?: boolean — highlight Sat/Sun (weekStartsOn: Monday)
- dates?: (string | Date | { date, label? })[]
- color?: default #f2f2f2
- isWeekend?: (date) => boolean — custom predicate

blockDates?: BlockDateRange[]
- { start, end, label?, color? } — light rose default; unavailable ranges. start/end support date or datetime; datetime blocks render only from exact start time to exact end time, not as full-day bands.

eventMarkers?: EventMarker[]
- { id?, date, label, color?, labelTop? } — vertical dashed stripline + labeled callout
- date supports datetime for sub-day placement

draggableMarkerSnapPoints?: DraggableMarkerSnapPoint[]
- { id, date }[] — invisible snap targets; datetime supported. Takes priority over snapToGrid.
- Resolved only when a drag callback is registered; onDraggableMarkerDragToSnapPoint enables snap-index tracking during drag

draggableMarkers?: DraggableMarker[]
- { id, date, label?, color?, draggable? } — solid vertical line (today-marker style), draggable
- onDraggableMarkerDragStart / onDraggableMarkerDrag / onDraggableMarkerDragEnd — opt-in; omitted handlers are not called
- onDraggableMarkerDragToSnapPoint — opt-in snap-point callback (phase: drag | end)
- No drag/click handlers → static lines only (no hit targets, pointer-events: none)
- Snap on release aligns to column boundaries (same x as vertical grid lines); use local yyyy-MM-dd when persisting dates from callbacks
- Use for history scrubbers, as-of dates, audit playback in consuming apps
- Respects snapToGrid on drag end; clamps to minDate/maxDate when set

Layers render in the timeline header/body (holidays and blocks) and full-height overlay (events, draggable markers).

## Tooltip

Built-in and custom task tooltips share an optimized overlay: position updates are imperative (no chart re-render on mousemove).

Props:
- showTooltip?: boolean — default false. Built-in floating tooltip: name, start, end (time when non-midnight in display timezone; see `timezone` prop).
- renderTaskTooltip?: TaskTooltipRenderer — custom tooltip UI. When set, tooltips are enabled and replace the built-in content.

Types:
```ts
type TaskTooltipChangeHandler = (patch: Partial<GanttTask>) => void;

type TaskTooltipRenderer = (
  task: GanttTask,
  onChange: TaskTooltipChangeHandler,
) => React.ReactNode;
```

renderTaskTooltip(task, onChange):
- task — hovered task (live dates during drag/resize)
- onChange(patch) — apply Partial<GanttTask> to the task (updates store + onTasksChange). Supports name, progress, start, end, color, borderColor. readOnly tasks ignored.

Tooltip enabled when: showTooltip || renderTaskTooltip

Built-in example:
<GanttChart tasks={tasks} showTooltip onTasksChange={setTasks} />

Custom example:
<GanttChart
  tasks={tasks}
  onTasksChange={setTasks}
  renderTaskTooltip={(task, onChange) => (
    <MyTooltip task={task} onChange={onChange} />
  )}
/>

Custom tooltips: style your own component. Shell uses .rg-task-tooltip-shell (position only); child gets pointer-events: auto for buttons/inputs.
Built-in uses .rg-task-tooltip (themed via --rg-tooltip-* on .rg-gantt).

Performance (tooltip overlay only — chart/timeline do NOT re-render):
| Event | Chart | Tooltip content |
|-------|-------|-----------------|
| mousemove (hover) | no | no — position via DOM |
| drag / resize move | no | only when start/end/progress/name change |
| mouse enter / leave | no | show / hide |
| onChange from tooltip | no | only when patched fields change |

onTaskHover: fires on mouse enter and leave only (task: null on leave). NOT fired on mousemove.
clientX/clientY included on enter. Use for external hover state — do not setState on every move from this hook.

During drag/resize, tooltip content (built-in or custom) updates via internal syncTooltip — not via onTaskHover.

Implementation: TaskTooltipProvider + imperative TaskTooltipController (src/components/Tooltip/). useTaskTooltipOptional() available inside chart tree (internal; not exported from package entry).

## Custom rows

customRows?: CustomRowDefinition[]

CustomRowDefinition:
{
  id: string,
  meta?: TMeta,
  height?: number,  // px; defaults to chart rowHeight
  sticky?: 'top' | 'bottom',  // pin row below header or above viewport bottom; omit = inline (scrolls with tasks, rendered after task rows)
  cells: Record<columnKey, (ctx) => ReactNode | Promise<ReactNode>>
}

Row placement (display order inside scroll area):
1. sticky top tasks (GanttTask.sticky: 'top')
2. sticky top custom rows (CustomRowDefinition.sticky: 'top')
3. scrollable tasks (no sticky)
4. inline custom rows (no sticky — default footer behavior)
5. sticky bottom custom rows (CustomRowDefinition.sticky: 'bottom')
6. sticky bottom tasks (GanttTask.sticky: 'bottom')

Sticky rows use CSS position: sticky. Top rows stack below the 52px column header (top offset 52px + prior sticky row heights). Bottom rows stack from the viewport bottom. Sidebar, middle panel, and timeline stay height-synced via `.rg-sync-scroll`.

Timeline DOM (sticky requires a tall row container — same pattern as sidebar):
.rg-timeline-scroll (scroll container)
  .rg-timeline-inner
    .rg-timeline-header (sticky top: 0)
    .rg-timeline-rows (full content height — all row sections)
      StickyTaskTimelineRows (top) — .rg-sticky-task-timeline-row per task, no short wrapper
      CustomRowsTimeline sticky top — .rg-custom-row-timeline-band per row, no .rg-custom-rows-timeline wrapper
      .rg-timeline-body (scrollable tasks only)
      CustomRowsTimeline inline — .rg-custom-rows-timeline wrapper (footer border)
      CustomRowsTimeline sticky bottom — bands only
      StickyTaskTimelineRows (bottom)

Sidebar equivalent: .rg-task-list-body holds all row sections (sticky top → scroll → sticky bottom) in one tall block.

Implementation note: sticky timeline rows must NOT be wrapped in a short-height parent (e.g. a div sized only to the pinned rows). CSS sticky is clipped to ancestor bounds; a ~36px wrapper prevents gantt bars from pinning while sidebar labels still stick inside .rg-task-list-body.

Sticky task bars render via StickyTaskTimelineRows (per-row SVG + TaskBar) outside TimelineBody. Sticky top/bottom tasks are excluded from TimelineBody (scroll section) but remain in the full tasks array for resolveTasks, dependencies, and callbacks.

Example — baseline bar pinned top + footer bands pinned bottom:
const tasks = [
  { id: 'baseline', name: 'Project baseline', start: '2026-01-01', end: '2026-12-31', sticky: 'top', color: '#6366f1', readOnly: true },
  /* ...many scrollable tasks... */
];
const customRows = [
  { id: 'legend', sticky: 'bottom', height: 32, cells: { name: () => 'Legend', __timeline__: () => <FooterLegend /> } },
  { id: 'totals', sticky: 'bottom', height: 28, cells: { name: () => 'Totals', __timeline__: () => <FooterTotals /> } },
];
<GanttChart tasks={tasks} customRows={customRows} height={520} />

Cell keys:
- Match columns[].key and middleColumns[].key for sidebar cells
- '__timeline__' — full-width band inside .rg-timeline-rows (scrolls/zooms with chart; sticky bands pin within .rg-timeline-scroll)

CustomRowCellContext (snapshot when the cell generator runs):
{ rowId, columnKey, columnIndex, rowIndex, zoomLevel, rangeStart, rangeEnd, scale, columnWidth, timelineWidth, msPerPixel, rowHeight, scrollLeft, viewportWidth, visibleColumnStart, visibleColumnEnd, viewportColumnStart, viewportColumnEnd, columnScrollBufferPercent, meta? }

Async cells:
- Promise supported; fires onCustomRowCellReady / onCustomRowCellError
- First load: shows loading ellipsis (`.rg-custom-cell--loading`)
- Reload (zoom, range, row height, etc.): keeps previous content visible until the new result arrives (no flash)
- Generator re-runs when structural metrics change (zoom, columnWidth, timelineWidth, msPerPixel, range, rowHeight, row meta/height) — NOT on horizontal scroll or virtual column window shifts

Timeline band pattern — return a component that uses the hook for scroll/window:
function MyStrip() {
  const { range, msPerPixel, columnWidth, scale, timelineWidth, zoomLevel, rowHeight, visibleColumns } = useGanttTimeline();
  const width = range.pixelWidth ?? range.columnCount * columnWidth;
  // visibleColumns.startX/endX, scrollLeft, etc. update on scroll — do not rely on ctx for that
  return <div style={{ width }}>...</div>;
}
cells: { name: () => 'Label', start: () => '—', end: () => '—', __timeline__: () => <MyStrip /> }

useGanttTimeline() — must be descendant of GanttChart (GanttTimelineProvider).
Returns: zoomLevel, scale, columnWidth, timelineWidth, range, rowHeight, msPerPixel, scrollLeft, viewportWidth, visibleColumns (buffered window), viewportColumns (tight viewport), columnScrollBufferPercent.
For __timeline__ cells: use this hook (not CustomRowCellContext) for scroll position and visible column window.

useGanttTimelineOptional() — returns null outside chart

Inline custom rows (no sticky) render below scrollable task rows in sidebar + timeline. Sticky custom rows render in top/bottom zones (see Row placement above).

## Sticky rows (tasks + custom)

GanttTask.sticky and CustomRowDefinition.sticky: 'top' | 'bottom'

| sticky | Behavior |
|--------|----------|
| 'top' | Row pinned below the 52px header; remains visible when scrolling down through large task lists |
| 'bottom' | Row pinned to the viewport bottom; remains visible when scrolling up |
| (omit) | Scrolls with main content |

Works for both task rows (sidebar + gantt bar) and custom rows (sidebar cells + __timeline__ band).

Multiple sticky rows on the same edge stack with computed offsets (top: 52px + heights above; bottom: heights below).

readOnly sticky top tasks are a common pattern for project baselines / summary bars spanning the full range.

DOM: data-sticky="top" | "bottom" on .rg-task-row, .rg-custom-row-timeline-band, .rg-sticky-task-timeline-row
CSS: .rg-timeline-rows, .rg-row--sticky, .rg-sticky-task-timeline-row (timeline task bars); .rg-custom-row-timeline-band.rg-row--sticky (timeline custom bands)
Token: --rg-sticky-row-bg (opaque background so scrolled content does not show through)

data-testid: sticky-task-timeline-top, sticky-task-timeline-bottom (first band in each sticky section), custom-rows-sticky-top, custom-rows-sticky-bottom, custom-rows (inline footer only)

Demo: demo/stickyRowsDemo.tsx — 32 scrollable work packages, indigo baseline bar (sticky top), two sticky bottom custom footer rows.

## Performance model

TaskStore: external store; per-task version counters.
TaskBar: React.memo + custom comparator; subscribes to single task version via useTaskVersion.
Drag/resize: updateTask() bumps one version → only that bar re-renders.
Grid, headers, dependency layer: separate memoized components.
Timeline context (scroll/zoom/range): ref-stabilized via metricsSignature — consumers skip re-render when values unchanged.
Task tooltip: isolated TaskTooltipOverlay; GanttChart does not hold tooltip position state. Memoized panels (TimelineBody, TaskListPanel, etc.) skip re-render during tooltip mousemove.

Advanced: import TaskStore directly for custom integrations.

TaskStore API:
- constructor(initial: GanttTask[])
- subscribe(listener) → unsubscribe
- getSnapshot(), getVersion(), getTaskVersion(taskId)
- setTasks(tasks), updateTask(taskId, patch), replaceTasks(tasks)

## Theme (light / dark)

theme?: 'light' | 'dark' | 'auto' — default 'light'
Applies class `rg-theme-{theme}` on `.rg-gantt`.

| value | Behavior |
|-------|----------|
| light | Default light surfaces and text |
| dark | Twilight navy palette (#0c1222 base), elevated surfaces, brighter accents |
| auto | Light by default; follows OS `prefers-color-scheme: dark` |

Dark mode design notes:
- No pure black (#000) or pure white (#fff) text — uses #0c1222 / #e2e8f0
- Elevation via lighter surfaces (--rg-surface-raised), not heavy shadows
- Brighter bar fill (#60a5fa) and handles (#38bdf8) for contrast
- Borders use rgba(255,255,255,0.1)

Example:
<GanttChart tasks={tasks} theme="dark" />
<GanttChart tasks={tasks} theme="auto" />

Demo: topbar theme toggle cycles System → Light → Dark (localStorage `rg-demo-theme`).

## Limitations (do not assume)

- __timeline__ custom cells do not re-run their generator on scroll; use useGanttTimeline() for live scroll/window data (ctx.visibleColumnStart etc. are snapshots)
- lag is a label only; it does not move or constrain bars
- onGanttHover for blocks may not fire when pointer is over a task bar (bars sit above block hit layer)
- GanttChartProps.children unused
- No built-in context menu UI (use onGanttContextMenu + your own menu component)
- No built-in task creation/editing forms (use renderTaskTooltip + onChange for inline edits)
- No resource assignment / multi-project views
- Middle panel start/end show date only (not time); formatted in `timezone` when set, else browser locale
- Sticky tasks are excluded from scrollable TimelineBody hit layer; timeline empty-area clicks (rowIndex) refer to scroll-section rows only
- When extending sticky timeline rendering: keep pinned rows as direct children of .rg-timeline-rows; do not wrap in a container sized only to pinned row height
- Dependency arrows use full task list row indices; pinned rows may affect visual arrow paths when sticky tasks are not adjacent to dependents in scroll order
- Week starts Monday (date-fns weekStartsOn: 1)
